Key Design Decision

The progression service is a separate microservice — it does not replace the main app's database. It listens to events via webhooks and maintains its own gamification state independently.

Backend Integrations

Two Communication Patterns

JWT/users/me/*

User-facing routes. Frontend calls these directly with a Bearer token after login. Used for real-time profile updates and immediate feedback.

API KEY/webhook/*

Service-to-service routes. The main backend calls these with a secret API key. Used when the main app owns the lesson/quiz logic and just reports results.

Why Two Auth Methods?

JWT = User identity (who is making the request)
API Key = Service identity (which system is calling)

Webhooks use API keys because the main app acts on behalf of users — it already verified them in its own auth system.

Step-by-Step Flow

Step Action System
1 User clicks "Complete Lesson" Frontend
2 Save completion to MySQL Main App
3 POST /webhook/lesson-complete Main App → Progression
4 Verify API key, find/create user Progression Service
5 Add +50 XP, check for level-up Progression Service
6 Return updated stats Progression → Main App
7 Display level-up animation Frontend

Critical Point

The main app does not wait for the webhook response to show "Lesson Complete" to the user. The webhook is fire-and-forget from the user's perspective — the XP update happens asynchronously.

Level-Up Mechanic

How addXP() Works

while (xpAdded > 0) { const needed = getXPForLevel(user.level); if (user.xp + xpAdded >= needed) { xpAdded -= (needed - user.xp); user.xp = 0; user.level++; levelsGained++; } else { user.xp += xpAdded; xpAdded = 0; } }
  • XP bar resets to 0 on level-up
  • Excess XP carries to next level
  • Multiple levels in one action possible
  • levelsGained tracks promotions

Technical Defense — Design Decisions

Why a Separate Microservice?

Separation of concerns. The main app handles academics; this handles gamification. Either can be modified, scaled, or replaced independently without breaking the other.

Why In-Memory Storage?

Speed — no DB latency for leaderboard queries. Simplicity for MVP. Tradeoff: data loss on restart. Production would use Redis for persistence with similar performance.

Why Two Auth Methods?

JWT for user identity (frontend → backend). API key for service identity (backend → backend). Prevents users from spoofing webhook calls to fake their own XP.

Why Exponential XP Curve?

Creates long-term engagement. Early levels feel rewarding (quick wins), later levels feel prestigious (rare achievements). Standard pattern in RPG and mobile game design.
